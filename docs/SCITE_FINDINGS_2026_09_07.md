Scite searches also returned preprints: those versions were excluded, including the arXiv versions of papers for which a published version exists. The original BERTopic preprint is not used as peer-reviewed evidence here. This is a focused review, not an exhaustive systematic review.

## Correcting the regex/semantic terminology

There are three different pieces of the pipeline. Conflating them was misleading:

1. **Original X retrieval/filter comparison:** the merge notebook has a strict regex/keyword stream and a broad semantic stream scored by MiniLM. Cell index 11 uses positive-reference cosine similarity >= 0.50 and positive-minus-negative margin >= 0.06. This is a real embedding-based semantic filter. Comparison/export code exists, but this review does not claim a newly computed validation result for it.
2. **Reddit contextual filtering:** saved merge cells 41/43 construct `POST CONTEXT: ... COMMENT: ...`; cell 46 applies domain/listing cues to contextual filter text. This includes the original thread post. It is not necessarily the immediate parent comment and does not by itself imply LLM reasoning.
3. **The later outlier audit:** my 'strict' and 'broader' candidate buckets were both keyword/context heuristics. The broader bucket was not MiniLM. The old 12-word/direct-keyword rule should not be adopted as a final relevance requirement. The earlier measured recall comparison applied to these heuristics, not to the original regex-versus-MiniLM comparison.

The topic notebook embeds `clean_text`, so a reply can have passed contextual domain filtering and still become a BERTopic outlier because its embedding lacks context. This is a concrete reason to test contextual representation. It is not proof that context explains every outlier.

## How to fix the current problem without refitting prematurely

Separate **relevance**, **substantive content**, and **topic assignment**. HDBSCAN's -1 means no accepted density cluster under the chosen representation/parameters; it does not mean irrelevant. An assigned topic can still contain noise.

First validate a contextual relevance/content filter on a small sample. Preserve short informative replies, label generic acknowledgments separately, distinguish a reply from an advertising parent, and flag repeated filler without erasing useful content. Test three comparable routes on the same reference records: keyword rules, MiniLM, and contextual LLM classification. Test the LLM with and without context to isolate context's contribution. Do not silently substitute model labels for the independent human test set.

After this pilot, expand an untouched evaluation sample and agree on acceptable errors/abstentions. Only then apply the selected filter to the full corpus and refit. For clustering, compare target-only versus carefully delimited contextual embeddings and a small HDBSCAN sensitivity grid on the same frozen corpus. Parent text repeated across many replies can itself dominate embeddings, so whole-thread concatenation is a hypothesis to test, not an automatic fix. Keep original target text, context and input construction separately.

Outlier reassignment can later be tested for high-confidence, relevant cases with an abstention option. Forcing every record into a nearest topic produces coverage, not proof of meaning. A cosine-distance cut on topic centroids changes grouping of existing topics; it does not fix missing reply context or recover -1 by itself. Do not optimize for zero outliers or 25 equally sized groups.

## Work already prepared and order of operations

The local review package contains **80 distinct records: 60 outliers and 20 assigned controls**, sampled from the latest refit. The first **32** calibrate definitions; **48** are held out from tuning. It includes 68 Reddit records and 12 X records. Immediate parent text was resolved for 51 of its 54 Reddit comments. Sampling categories and topic IDs are hidden from the annotator packets; source IDs remain in a private key. Read [the guide](../analysis/context_review_2026_09_07/REVIEW_GUIDE.md). These are blank human annotation packets, not completed validation results.

| Workstream | First concrete step | What completion establishes |
|---|---|---|
| Rejected records / outlier recovery | Aaron and Prajwal independently label the 32 calibration records. Compare the frozen candidate methods on the 48 held-out records, then expand the test set. Separately sample earlier removed records from the relevant preprocessing checkpoint. | Initial failure modes and a feasible codebook; later a properly sampled evaluation of false removals/recovery. The current packet alone does not audit all earlier rejects. |
| Topics and groups | Once content filtering is settled, rate representative and random messages from the largest/mixed topics and a random set of smaller topics. Compare grouping alternatives using the same records and definitions. | Evidence that topics and merged groups are interpretable; not just a lower outlier count. |
| Sentiment / expectations | Add a separate small sample labelled for opinion target, polarity, and future-versus-past orientation after relevance definitions are stable. Begin with housing expectations or aspect-specific sentiment rather than numerous new indicators. | Whether the proposed NLP label measures the intended construct on Dubai text. Existing relevance labels cannot validate sentiment. |
| Deduplication | Compare raw legitimate-message attention, same-author-per-week capped attention, and a topic-training template-collapse variant while preserving original row mappings. Review near-duplicate pairs for changed numbers/negation. | How much the result depends on the repeat policy; no universal threshold is assumed. |
| DLD comparison | Freeze one primary transaction-count outcome and calendar; compare attention and validated sentiment separately, with a very small prespecified set of leads. | Exploratory association within January–April 2026, with coverage and uncertainty reported. Four months remains the scope; no claim that extra daily rows solve temporal dependence. |
